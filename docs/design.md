# MoonAPRS 设计说明

## 1. 目标与边界

MoonAPRS 是一个纯 MoonBit 的 APRS / AX.25 协议栈。设计目标是：

1. **协议正确**：以公开规范和已知抓包字节为准，位级编码可回归验证。
2. **零平台依赖**：核心库不依赖文件系统或网络，native / Wasm / JS 三端可编译。
3. **分层清晰**：比特层（AX.25/HDLC/KISS）与语义层（APRS 报文）解耦。
4. **可演示**：CLI 与浏览器演示直接使用同一套库代码。

不包含的内容：射频调制、声卡 TNC；APRS-IS 实时客户端依赖原始 TCP 套接字，仅原生目标提供（核心引擎与传输抽象仍与后端无关）。

## 2. 分层

```
cmd/main ────────────────┐
web (MoonBit → JS) ──────┤
                         ▼
                      lib/svg        投影与渲染
                         ▲
                      lib/track      航迹、几何、简化
                         ▲
                      lib/aprs       TNC2、APRS 语义、APRS-IS
                         ▲
                      lib/ax25      AX.25 帧、CRC、HDLC、KISS
```

依赖单向向上，`lib/ax25` 不依赖任何本项目包。

## 3. AX.25 层

### 3.1 地址字段

每个地址 7 字节：6 个字符各左移 1 位（ASCII `A` = 0x41 → 0x82），第 7 字节为：

```
bit 7   C / H 位（目标地址为命令位，中继为已转发位）
bit 6-5 保留，置 1
bit 4-1 SSID（0-15）
bit 0   扩展位：地址字段最后一字节置 1
```

SSID 字节的基础值为 `0x60`；目标地址额外置 `0x80`（APRS 使用命令帧）。

### 3.2 帧结构

`地址字段 | 控制字段 | PID | 信息字段 | FCS`

- UI 帧控制字段 `0x03`，PID `0xF0`（无网络层）。
- FCS 为 CRC-16/X.25，反射多项式 `0x8408`，初值 `0xFFFF`，结果异或 `0xFFFF`，
  低字节先发送。

### 3.3 HDLC 与 KISS

- HDLC 发送端在连续 5 个 `1` 后插入 `0`；`bit_stuff` 返回有效位数，便于去除
  字节对齐填充。
- KISS 以 `0xC0` 分帧，`0xDB` 转义：`0xDB 0xDC` 表示 `0xC0`，`0xDB 0xDD` 表示
  `0xDB`。`KissDecoder` 支持跨多次 `feed` 的增量解析。

## 4. APRS 语义层

### 4.1 TNC2

`SRC>DST,PATH1,PATH2*:info`。路径末尾 `*` 表示该中继已转发（`has been repeated`）。

### 4.2 报文分派

按信息字段首字符分派：

| 首字符 | 类型 |
|---|---|
| `!` `=` | 位置（无时间戳） |
| `/` `@` | 位置（带 `DDHHMMz` 时间戳） |
| `;` | 对象 |
| `)` | 条目 |
| `>` | 状态 |
| `_` | 无位置气象 |
| `T#` | 遥测 |
| `:` | 消息 |
| `?` | 查询 |
| `}` | 第三方报文 |
| `` ` `` `'` | Mic-E 位置（需要目的地址） |

### 4.3 位置

- 非压缩：`ddmm.hhN/sssmm.hhW`，纬度 8 字符、符号表字符、经度 9 字符、符号码、
  注释。空格表示位置歧义（低位数字被隐去）。
- 压缩：符号表 + 4 字符 base-91 纬度 + 4 字符 base-91 经度 + 符号码 + 3 字符
  状态。`lat = 90 - v/380926`，`lon = -180 + v/190463`。
- 符号码为 `_` 时视为气象站，注释以 `DDD/SSS` 开头（风向/风速），其余为
  `c/s/g/t/r/p/P/h/b` 等定长字段。

### 4.4 Mic-E 位置

Mic-E 把纬度藏进 AX.25 目的地址的六个字符里，因此解码必须同时拿到信息字段与目的
地址，`AprsPacket::parse` 通过 `parse_info_with_dest` 传入。

- 字符映射：`0`-`9` 为数字、标志位 0；`A`-`J`、`P`-`Y` 为数字 0-9、标志位 1；
  `K`/`L`/`Z` 表示空格（位置歧义）。
- 六个数字组成 `ddmmhh`；第 4/5/6 字符的标志位分别是「北纬」「经度 +100」「西经」。
- 信息字段首字符 `` ` `` 表示当前定位、`'` 表示旧定位；随后三字节各减 28 得到
  经度度/分/百分分，再三字节解出速度与航向。
- 速度原始值 ≥ 800 表示 800-899 段（减 800），≥ 600 表示 600-699 段（减 600）；
  航向原始值 ≥ 400 时减 400。
- 第 8 字节为符号码、第 9 字节为符号表，其后为状态文本。

前三个字符的标志位组成 3 位 Mic-E 消息码（A/B/C），用于表示自定义/标准消息。

### 4.5 APRS-IS

passcode：以 `0x73E2` 为初值，按字符对异或（高字节在前），取低 15 位。SSID 不参与。

### 4.6 时间戳

APRS 时间戳无年份，且分四种形态：

| 形态 | 含义 | 用途 |
|---|---|---|
| `DDHHMMz` | 日/时/分 UTC | 位置、状态、对象 |
| `DDHHMM/` | 日/时/分 本地时间 | 同上 |
| `HHMMSSh` | 时/分/秒 | 特殊报文 |
| `MMDDHHMM` | 月/日/时/分 | 气象 |

解析时校验日/月/时分秒范围。`DateTime` 用 Hinnant 的 `civil_from_days` /
`days_from_civil` 算法在 proleptic 公历与 Unix epoch 间换算（负数 epoch 经
`floor_div` 修正截断）；`resolve_aprs_time(ts, reference, tz)` 取“不晚于参考时刻的
最近匹配点”，把缺少年份的时间戳锚定为完整 UTC 日期时间：`DayZulu`/`HourMinuteSecond`
按 UTC，`DayLocal`/`MonthDayHourMinute` 先应用本地时区偏移。mdhm 最多回溯 10 年、
day 最多回溯 24 个月，从而正确处理跨午夜、跨月与跨年。航迹点携带 `epoch`，GPX /
GeoJSON 据此输出 ISO 8601 时间，速度计算在两点都有 epoch 时走精确秒差。

### 4.7 符号表

符号由“表字符 + 符号码”两级组成：`/` 为主表，`\` 为备表，其他字符视为备表的
overlay。`SymbolInfo` 同时给出名称与粗类别（vehicle/weather/infrastructure/…），
供 CLI 与地图标记复用。

### 4.8 公告与 NWS

消息地址 `BLN0`-`BLN9` 视为公告，正文前 5 字符为主题；`NWS` 前缀视为气象部门
消息。分类不影响消息本身的解析，只提供展示与路由用的标签。

### 4.9 去重、会话与客户端

APRS-IS 上同一报文会经不同中继到达。`DedupeWindow` 以“源>目标:信息字段”为签名，
保留最近 N 条，命中即丢弃。`IsSession` 维护登录、keepalive、`#` 注释解析与计数。

`IsClient` 是传输无关的客户端引擎：定义 `IsTransport` trait（`read_line` /
`write_line` / `close`），负责发送登录行、分类服务器行、确认登录、去重与计数，
并在 `read_line` 返回 `None`（EOF 或读超时）时以指数退避重连（1s 起，封顶 30s）。
网络 IO 由 `IsTransport` 实现提供：`cmd/main` 附带原生 TCP 传输（C FFI，阻塞式
行读取，90s `SO_RCVTIMEO` 作 keepalive 看门狗），驱动 `is-live` 命令；Wasm/JS
因无原始套接字，仅编译存根。同一引擎也可接 stdio 或测试双工。

`is-live --out base [--count n]` 把位置包实时 `ingest` 进 `TrackStore`（以当前时刻
锚定 epoch），收满 n 个点时令 `on_event` 返回 `false` 干净退出并导出 `base.gpx` /
`base.geojson`；未设 `--count` 时每积累 25 个点增量重写一次导出，避免 Ctrl-C 丢失
全部数据。原生无信号处理，故用计数与节流代替退出钩子。

## 5. 航迹与渲染

- 大圆距离使用 haversine，地球半径 6371.0088 km。
- 重复信标：与上一个点距离小于 20 m 时忽略。
- 速度/航向：相邻点若都已锚定 epoch，用精确秒差计算速度（跨月/跨年正确）；否则
  回退到同一报文序列内的分钟差（24 小时回绕）；航向取初始方位。
- Douglas-Peucker 在局部等距平面上做垂距判断，容差单位为 km。
- Web Mercator：`y = 0.5 - ln(tan(π/4 + φ/2)) / 2π`；投影后保持纵横比并留边距。
- 导出：GPX 使用 `<trkpt lat lon>`，已锚定的点输出 `<time>`（ISO 8601），原始 APRS
  注释放在 `<desc>`；GeoJSON 输出 LineString，坐标顺序为 `[lon, lat]`，并在 properties
  中输出平行的 `times` 数组。

## 6. 测试策略

- 位级：CRC 标准校验值 `0x906E`、地址字段已知字节、HDLC 填充位计数。
- 往返：帧编码 → 解码、KISS 编码 → 流式解码。
- 语义：规范示例（压缩位置 `!/5L!!<*e7>7P[` → 49.5N, 72.75W）、Mic-E 规范示例
  （`DG0P2R` + `` `rG9l `` → 36°00.22′N 86°43.29′W）、歧义位置、
  气象、遥测、消息/ACK、对象、条目。
- 几何：London–Paris 距离/方位、Maidenhead、共线点简化、速度/航向。
- 导出：GPX 元素计数与转义、GeoJSON 坐标顺序与 FeatureCollection 结构。
- 健壮性：合法报文的所有前缀、垃圾输入、控制字节与 2000 字符负载均不崩溃。
- 渲染：空航迹与单航迹均输出合法 SVG。
